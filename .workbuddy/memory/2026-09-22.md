## 14:50 音效方案（未实施，等你拍板）

产出 `音效方案-未竟-20260922.md` + `android/gen_sfx.py` + `android/sfx-preview/*.wav`（9 个，385KB）。

核心判断：
- **音效必须比触觉保守**。振动私密、声音公开（会议室/地铁），所以不做点击音/导航音，
  只在「成就时刻」响。默认 7 响 / 2 关（`undo` 撤销不该有正反馈；`step_soft` 高频重复会变噪音）。
  「通知栏打卡」后台路径**只振不响**（前台判断拦截）。
- **响度即层级**，用峰值设计代替音量滑块：里程碑 -0.9dB / 成就 -1.3~2.2 / 确认 -3~5 / 细节 -7.5。
- **音数编码等级**：2 音=单习惯、3 音=一组计划、4 音=全天；全部落 C 大调自然音，9 音效共用一套音高体系。
- **冲突优先级**：一次事件只播最高级（`achieve_day` > `achieve_plan`/`counter_limit` > …）。

技术取舍（见文档 §7 的 4 个决策点，均未拍板）：
- 走**音效流 `USAGE_ASSISTANCE_SONIFICATION`**（映射 STREAM_SYSTEM）而非媒体流：
  手机"静音模式"只静铃声+通知，走媒体流会导致**静音下打卡照样出声**，不可接受。
  代价是系统音量 0 时听不见 → 必须配设置页音量诊断 + 试听按钮。
- 建议引入 `util/Feedback.kt` 门面（冲突优先级只写一遍，现有 `Haptics.play` 有 15 处调用分散在 8 文件）。
- 节流 **150ms**（比 Haptics 的 70ms 长，因音效有尾音会叠成噪音），**分档独立计时**（照搬 Haptics 结论）。

来源：**本地合成**（本机无 ffmpeg/numpy，用标准库 `wave`+`math` 数值生成 FM 铃铛），原创 CC0 零版权负担；
脚本参数化，改 `fm_index`/`tau_ms` 30 秒重调。备选 CC0 素材库可只换文件不动代码。

已踩/已写的坑：
- WAV 首尾必须强制淡入淡出（2ms/4ms），否则波形 0→非零突跳会爆出「咔」声。
- 尾部裁到 -58dB 省 10~20% 体积。
- 滑音必须**相位累加**，直接代入 `sin(2πft)` 会算错相位产生杂音。
- SoundPool `load()` 异步 → 首次 play 可能无声，需 `setOnLoadCompleteListener` + 首帧后预热（**不放 Application.onCreate**）。
- `R.raw` 硬引用即编译期保护：资源缺失 → 编译失败，比单测硬。
- 🚨 「今日全部完成」现有代码**没有**触觉调用点，新增时**必须做边沿检测**
  （`remember` 记上次完成率，首次 null 只记录不播），否则每次进今日页都响一遍。

验证诚实说明：`Build SUCCESSFUL` 与"真的出声"隔 4 层，截图/录屏都验不了音效；
MuMu 只能验 logcat 里 `play()` 被调到 + `dumpsys audio` 有流，**最终音色只能人工在真机听**。
→ 所以先出 `sfx-preview/` 让你定音色，避免装到手机才发现要改。

⚠️ 别信网上「Android 14 废除了 REQUEST_INSTALL_PACKAGES，自更新已死」那套 —— 那是伪造的
AOSP 注释。官方行为变更文档与 CDD 都要求设备支持。真正被禁的是 **Google Play 上架应用**
用该权限自更新；本应用不上架，不受约束。

### Gitee 实测

- API `GET /api/v5/repos/{o}/{r}/releases/latest` ✅，字段与 GitHub 同构
