`android/QA复核与修复方案.md`。

**复核结论**
1. 编译阻断 ✅ 属实 — HistoryScreen:57-58/82 引用 ViewModel 不存在的
   `allHabits` / `allCheckIns` / 两参数 `toggleCheckIn`。Repository 里已有对应
   Flow，只是没转发到 ViewModel。
2. 未来日期可打卡 ✅ 属实 — 报告漏报「切月后 selectedDate 不与月份联动」，
   导致月历高亮与下方计划清单显示不同日期。
3. 排期/计数器未落地 ✅ 属实 — `isHabitScheduled` 是 CalendarMonthView 的
   private 函数，今日页/统计调用不到，靠默认值侥幸对齐。今日页、月历、
   通知「一键完成」对计数器有三种不同完成语义。
4. 提醒链路 ⚠️ 结论对机理不准 — CheckInActionReceiver:30 其实查了 habit，
   但只取字段不判空；真正崩点是 CheckIn 的 `ForeignKey(onDelete=CASCADE)`。
5. 破坏性迁移 ✅ 属实 — 另叠加 `exportSchema=false`，将来无法用 AutoMigration。
6. 权限无反馈 ✅ 属实 — 但报告把 SCHEDULE_EXACT_ALARM 与 USE_EXACT_ALARM
   混为一谈；Android 13+ 声明 USE_EXACT_ALARM 后 canScheduleExactAlarms() 恒 true，
   降级只在 API 31-32 发生。

**补充发现的 3 个隐患（报告未提）**
- A. `HabitDao.insert` 用 `OnConflictStrategy.REPLACE` + FK CASCADE →
   若以已存在 habit 走 insert 路径会连带删光该习惯全部打卡记录。建议改 IGNORE。
- B. 通知 ID / PendingIntent requestCode 靠 `habitId.toInt()` 与 `+100000` 偏移
   散落在三个文件，应集中在 NotificationHelper 生成。
- C. 计数器无 +1 入口，`toggleCheckIn` 只能 0↔1 横跳，App 内永远无法把
   目标 >1 的习惯标记完成。

**待拍板**：问题 3 走方案 A（完整实现排期+计数器 UI，需先把 isHabitScheduled
提取到 util/HabitSchedule.kt 共用）还是方案 B（砍字段收敛为纯每日习惯）。
version=1 尚未发布，现在改实体不需要写迁移。

## 第五轮：查明「手机 APK ≠ 网页版」根因（同日 20:20）

用户反馈装到手机的版本和网页版界面不一致。核查结论：**不是用户操作问题**，
根因是仓库里存在 **三份互不同步的「同一个 App」实现**。

### 三份实现对照
| # | 位置 | 技术栈 | 存储 | 状态 |
|---|---|---|---|---|
| 1 | `src/` | React 19 + TS + Tailwind 4 + Vite 8 | IndexedDB `HabitTrackerDB` v3 | 真实运行（本次起的 dev server） |
| 2 | `android/` | Kotlin + Jetpack Compose + Room | Room SQLite | 真实编译，11:21 出过 `app-debug.apk` |
| 3 | `src/services/androidSources.ts` | 内嵌的 Kotlin **源码字符串快照** | — | **残缺、过时**，仅供网页版「导出 APK 工程」下载 |

三者**零代码共用**。第 1、2 份之间甚至连数据也不互通。

### 导航栏差异（结构性，非 bug）
- **`android/` 只有 3 个 tab**（`MainScreen.kt:86-103`）：今日打卡 / 历史回顾 / **习惯管理**。
- **`src/` 有 4 个 tab**（`App.tsx:899-974`）：今日打卡 / 日历与回顾 / **独立计数器** / **管理中心**。
- 「习惯管理」= 习惯列表增删改Managing；「管理中心」= 字号等设置。**名字像但不是同一个东西**。
- 「独立计数器」是 Web 版独有的 `StandaloneCounter` 实体（脱离习惯，如"冰箱里的可乐"）；
  Android 版的 `Habit.isCounter` 是「习惯内的计数目标」（如"喝水3杯"），**两者同名不同义**。
- Web 版 `Habit` 还有 `SubTask`（细化小计划），Android 版实体没有这个字段。

### codex 分支的影响面
`git diff --stat main..HEAD -- android/` **输出为空** → fd6bfa9 一行安卓代码都没碰。
GPT 那两个功能**只存在于 Web 版**，APK 里永远看不到。

### ⚠️ 第 3 份代码是坏的（发现待办）
`androidSources.ts` 里 13 个文件的静态快照：
- 含 **`StandaloneCounter.kt`** —— 真实 `android/` 目录里**根本不存在这个文件**。
- **缺 `HabitSchedule.kt`** —— 真实 `android/` 里第 2、3 轮刚加的核心判定（我们也改过它的算法）。
- 内嵌 `StreakCalculator.kt` 仍是**旧签名**（`(Set<String>, LocalDate)`），不含第 2 轮的排期感知重写。
- `HabitCard.kt`、`CalendarHeatMap.kt` 只有**一行占位注释**
  （`// 详见完整源码中的 ... 实现`），拿去编译必然失败。
→ 用户在网页版点「导出 Android Studio 工程」拿到的是这份残缺拷则，编译不出可用 APK。
  与第 2/3 轮修复全无关系，**必须整份废弃或改为从真实 `android/` 目录读文件**。
